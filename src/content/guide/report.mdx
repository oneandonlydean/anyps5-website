Test reports are how developers know what to fix next. A run that crashes with a full log is just as useful as one that reaches gameplay. Reports go to the **Game bring-up** discussions on GitHub, one thread per game, and show up on this site's [compatibility pages](/compatibility) on their own.

<Callout title="Coming soon: run reports">
AnyPS5 is learning to write `anyps5-report.json` next to the game after each run. Once your build does, [upload it](/report) and you're done, with no form to fill in. Until then, post in the discussions as described below.
</Callout>

## Find or start the thread

1. Search the [compatibility list](/compatibility) for your game. Its page has an **Open discussion** button that takes you to its thread.
2. If the game is not listed, open a [new bring-up report](https://github.com/boykopovar/AnyPS5/discussions/new?category=game-bring-up). Name it like `Game Name (PPSA01234)`.

## What to include

The form asks for these. Fill in what you know and leave the rest empty.

- **Title ID and content version**, not only the game name.
- **The AnyPS5 build**: the release (for example v0.1.3), or the commit and any pull requests applied on top.
- **Your system**: CPU, operating system, GPU and driver version.
- **The furthest point** the game reached: does not convert, stops before the first frame, logos or loading screen, menu, or in game.
- **What is shown** and **what stopped it**: the error, the exit code and the last lines of the output.

## How reports become a stage

Each game on this site has a stage on an eight-step ladder, from **Converts** to **Playable**. The furthest point in your report sets the stage, and maintainers can refine it. Results from development builds with extra patches show separately, so they don't overstate what the current release can do.

<Callout title="Something wrong on a game page?">
Each game page has a **Suggest a correction** link. A maintainer's correction always wins over automatic reports.
</Callout>
